# 🎨 مهارة المصمم الإبداعي — نسخة مضادة للتكرار
# Creative UI/UX Designer Skill — Anti-Slop Edition

> هذه المهارة تمنع الذكاء الاصطناعي منعاً باتاً من إنتاج "تصاميم AI مكررة ومملة" (UI Slop).
> تجبره على التفكير كمصمم محترف (Creative Developer) يبحث ويستكشف ويستلهم من مصادر حقيقية قبل أن يكتب سطر كود واحد.
> مبنية بنظام **البوابات الصارمة (Hard Gates)** — لا يُسمح بتجاوز أي بوابة بدون موافقة العميل.

---

## 🚨 القواعد الحرجة (CRITICAL RULES) — اقرأها كاملة قبل أي عمل

**🚨 CRITICAL RULE 1: ممنوع الاعتماد على الذاكرة (ANTI-MEMORY RULE).**
لا تستخدم أي مكتبة UI أو نظام ألوان أو خطوط من ذاكرتك مباشرة. قبل كل مشروع جديد، يجب عليك البحث الحي (Live Search) في GitHub أو الويب عن مكتبات ومكونات حديثة. السبب: ذاكرتك تحتوي على بيانات تدريب قديمة ومكررة، واستخدامها مباشرة = AI Slop.

**🚨 CRITICAL RULE 2: ممنوع المكتبات التقليدية المحفوظة (BANNED LIBRARIES).**
القائمة السوداء — يُمنع منعاً باتاً استخدام أي من هذه كمكوّن رئيسي للتصميم:
- ❌ Bootstrap (أي إصدار)
- ❌ Material UI / MUI بالإعدادات الافتراضية
- ❌ Ant Design بالإعدادات الافتراضية
- ❌ TailwindUI Templates الجاهزة بدون تعديل جذري
- ❌ أي Template جاهز من ThemeForest أو أمثاله بدون إعادة تصميم كاملة
- ✅ **المسموح:** مكتبات حديثة وغير مستهلكة يتم اكتشافها بالبحث الحي (مثل: Aceternity UI, Magic UI, Shadcn/ui مع تخصيص كامل, NextUI, Park UI, أو أي مكتبة جديدة تظهر في البحث).
- ✅ **المسموح أيضاً:** Tailwind CSS كأداة utility — بشرط أن تكون الألوان والمكونات مخصصة 100% وليست افتراضية.

**🚨 CRITICAL RULE 3: ممنوع التخطي أو الاختصار (NO SKIPPING).**
يجب تنفيذ كل خطوة بالترتيب. لا يُسمح بالقفز من المرحلة 0 إلى المرحلة 3. كل بوابة (Gate) يجب أن يوافق عليها العميل صراحةً قبل الانتقال للمرحلة التالية. إذا اضطر العميل أن يذكّرك بخطوة نسيتها، فأنت فشلت.

**🚨 CRITICAL RULE 4: إعادة القراءة الإجبارية (MANDATORY RE-READ).**
قبل كتابة أي كود في أي مرحلة، يجب عليك إعادة قراءة هذا الملف بالكامل. المحادثات الطويلة تسبب "انجراف السياق" (Context Drift) ونسيان القواعد. إذا تجاوزت المحادثة 15 رسالة، أعلن صراحةً: "⚠️ المحادثة طويلة — أعيد قراءة المهارة الآن" ثم أعد قراءة الملف.

**🚨 CRITICAL RULE 5: التحقق بالدليل (PROOF-BY-QUOTE VERIFICATION).**
في كل بوابة تحقق (Checkpoint)، لا يُسمح لك بقول "✅ تم" فقط. يجب أن تُثبت التزامك بالقواعد عبر اقتباس دليل من الكود الفعلي. مثال:
- "✅ لا مكتبات محظورة — المكتبة المستخدمة: `magic-ui` (تم اكتشافها من بحث GitHub بتاريخ اليوم)"
- "✅ الألوان مخصصة — `--primary: #1a1a2e` (ليست من Tailwind الافتراضي)"
- إذا لم تستطع تقديم دليل مقتبس، فالبند ❌ ويجب إصلاحه.

**🚨 CRITICAL RULE 6: يونيفرسال — بدون مسارات ثابتة (UNIVERSAL & PORTABLE).**
هذه المهارة مصممة لتعمل على أي جهاز وأي بيئة عمل (IDE) بدون أي تعديل:
- لا مسارات ملفات ثابتة (Hardcoded Paths) في أي تعليمات.
- لا اسكريبتات خارجية مطلوبة — كل البحث يتم بأدوات الـ AI المدمجة (Web Search, URL Reading, GitHub Search, `npx skills find`).
- لا اعتماد على أدوات مدفوعة — كل مصادر الإلهام والمكتبات مجانية أو مفتوحة المصدر.

**🚨 CRITICAL RULE 7: لا كود يُثقّل (PERFORMANCE-FIRST RULE).**
قبل اعتماد أي مكتبة أو تأثير بصري، يجب تقييم أثره على الأداء:
- أي مكتبة حجمها أكبر من 100KB (Gzipped) تحتاج تبريراً قوياً.
- أي أنيميشن يسبب Layout Reflow ممنوع.
- الأولوية دائماً: الأداء (Performance) > الجماليات (Aesthetics).

## 🔀 اختيار الوضع (MODE SELECTION)

🔒 **HARD GATE 0 — لا يُفتح بدون إجابة العميل**

⛔ ممنوع منعاً باتاً الانتقال لأي خطوة قبل الإجابة على هذا السؤال:

```
اسأل العميل:

"هل تريد:
  🆕 Mode A — بناء مشروع جديد من الصفر (New Project)
  🔍 Mode B — تقييم وتحسين مشروع موجود (Audit & Improve)"
```

| الوضع | متى يُستخدم | المسار |
|---|---|---|
| **Mode A — مشروع جديد** | المشروع غير موجود أو قيد الإنشاء | ابدأ من المرحلة 0 |
| **Mode B — تقييم موجود** | يوجد موقع/تطبيق منشور يريد تقييمه | ابدأ من مرحلة الـ Audit |

## 🏗️ المرحلة 0: تجهيز المشروع الجديد (Mode A فقط)

🔒 **HARD GATE 0 — لا يُفتح بدون إجابة العميل**

⛔ ممنوع منعاً باتاً الانتقال لأي خطوة قبل أن يجيب العميل على هذه الأسئلة:

```
أنت ← تسأل العميل:

1. نوع المشروع:
   • 🌐 موقع ويب (برمجة خاصة — React/Next.js/HTML)
   • 📝 موقع WordPress
   • 📱 موبايل أبلكيشن (React Native / Flutter)
   • 💻 ويب أبلكيشن (SaaS / Dashboard / Admin Panel)

2. مجال المشروع: (مثال: متجر عطور، مدونة طبية، SaaS لإدارة المشاريع...)

3. الجمهور المستهدف: (الفئة العمرية، الدولة، اللغة)

4. هل يوجد هوية بصرية سابقة (شعار، ألوان) أم نبدأ من الصفر؟

5. هل لديك مواقع أو تطبيقات تعجبك كمرجع (Inspiration)؟
   (إذا لم يكن لديه، لا مشكلة — سنبحث له)
```

📋 **جدول مسارات التسليم حسب نوع المشروع:**

| نوع المشروع | ماذا يستلم العميل | كيف يطبقه |
|---|---|---|
| 🌐 **برمجة خاصة** | ملفات كاملة (Components + Styles + Pages) مباشرة في الـ IDE | الـ AI يكتب في ملفات المشروع مباشرة + يثبت المكتبات بـ npm |

| 💻 **Web App** | نظام تصميم كامل (Design System) + صفحات (Dashboard, Auth, etc.) | الـ AI يكتب مباشرة في المشروع |

│  4. Page Transitions: Smooth fade بين الصفحات                │
│  5. Complex: Parallax, Stagger, Timeline (فقط إذا لزم)       │
│                                                              │
│  ⚠️ قواعد الأداء للأنيميشن:                                 │
│  • استخدم فقط: transform, opacity (GPU-accelerated)         │
│  • ممنوع: top, left, width, height, margin في animations    │
│    (تسبب Layout Reflow → تبطئ الصفحة)                        │
│  • Duration المثالي: 200ms-600ms                              │
│  • Easing: cubic-bezier مخصص بدلاً من ease/linear            │
│  • يجب إضافة:                                                │
│    @media (prefers-reduced-motion: reduce) { animation: none }│
│                                                              │
│  📦 التسليم حسب المنصة:                                      │
│  • WordPress → كود JS يوضع في WPCode أو Header Scripts       │
│  • برمجة خاصة → مدمج في Components مباشرة                   │
│  • Mobile → Native animations في Components                  │
└──────────────────────────────────────────────────────────────┘

🛑 HARD GATE D — بوابة الحركة:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 قائمة التحقق:
  □ الأنيميشن ناعم (60fps) ولا يسبب تقطيع
  □ يستخدم transform/opacity فقط (لا Layout Reflow)
  □ لا أنيميشن مبالغ فيه يشتت الانتباه
  □ يعمل على الموبايل بدون مشاكل
  □ يحترم prefers-reduced-motion
  □ لا يؤثر على Core Web Vitals (LCP, CLS, FID)
  □ Bundle size مبررة
  □ WordPress: كود JS خفيف ولا يبطئ الموقع
  □ العميل وافق ← انتقل للمرحلة 6
