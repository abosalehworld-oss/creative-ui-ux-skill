## الهدف
تشخيص دقيق لأي مشروع موجود قبل أي إصلاح.
القاعدة الذهبية: "لا تصلح ما هو غير مكسور."

## الخطوة A1 — جمع المعلومات

```
اسأل العميل:
1. نوع المشروع:
   • 🌐 موقع ويب → رابط الموقع
   • 📱 موبايل أبلكيشن → اسمه + المنصة (iOS/Android/الاثنين)
   • 💻 ويب أبلكيشن → رابط أو وصف
   • 🖥️ ديسكتوب → اسمه + نظام التشغيل
2. التقنية المستخدمة (WordPress / Shopify / React / Flutter / Electron...)
3. الشكاوى الموجودة (بطيء / تصميم قديم / لا يعمل على Mobile...)
4. صفحات أو شاشات بعينها تريد التركيز عليها؟
5. هل هناك كود مجهول المصدر تخشى المساس به؟
```

## الخطوة A5 — الإصلاح (حسب نوع المشروع)

```
🔴 حرجة (أولاً دائماً):
  ويب: JS defer، WebP، Lazy Loading، إزالة مكتبات غير مستخدمة
  موبايل: نقل Animations للـ UI Thread، FlatList optimization
  ديسكتوب: نقل العمليات الثقيلة لـ Worker threads

🟡 متوسطة (ثانياً):
  ويب: Font Preload، Critical CSS، Preconnect
  موبايل: تحسين Bundle Size، Image Caching
  ديسكتوب: High DPI، Keyboard Shortcuts

🔴 الوصولية (Accessibility) ليست اختيارية — مشاكلها الحرجة (تباين، كيبورد، Labels) تُعامل كحرجة.
🟢 خفيفة (اختيارية):
  Semantic HTML التجميلي، Micro-optimizations

⚠️ قاعدة "لا تثقّل":
  قبل إضافة أي أداة جديدة → احسب تأثيرها أولاً
  البدائل الخفيفة دائماً أفضل من المكتبات الضخمة
```
